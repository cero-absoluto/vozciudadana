## Corrección (esta PR)

La sonda de `issues` pasa a un recurso **existente** (el PR/incidencia `pr`, ya leído con 200 en `read.issues`) con un cuerpo **sin `body`**:

| Respuesta | Estado | Significado |
|---|---|---|
| 403 | PASS | permiso de escritura denegado antes de procesar la solicitud |
| 404 | FAIL (ambiguo) | el recurso existe: no prueba nada; nunca PASS |
| 422 | FAIL | superó el permiso y falló la validación del cuerpo: hay permiso de escritura (y no se creó nada) |
| 2xx | FAIL | escritura aceptada (inesperado): revisar a mano si hay efecto |
| otro / error de red | NO_PROBADO (infraestructura) | no concluyente |

Por qué no puede modificar aunque el token tuviera escritura: `body` es parámetro obligatorio de la API de creación de comentarios; una solicitud sin él es rechazada en validación (422) y no crea ningún comentario. No se toca ningún recurso real con PATCH/PUT/DELETE.

Límites declarados: la ausencia de efecto se apoya en el contrato documentado de la API, **no se ha verificado en vivo** (no hay token de escritura ni se autorizaron comentarios de prueba); que 403 preceda a 422 en un recurso existente es lo habitual pero tampoco se ha medido con un token de solo lectura. La primera ejecución real que use esta versión es la evidencia; si devuelve algo distinto de 403 queda como FAIL/NO_PROBADO, nunca PASS.
