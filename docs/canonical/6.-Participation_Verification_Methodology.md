# Participation Verification Methodology

**Project:** Voice Protest 
**Status:** canonical reference · v1.3 · 9 August 2026
**Companion documents:** privacy and data model (`docs/canonical/`), security audit (`docs/governance/`), audit trail (`docs/governance/`).

This document describes *how* Voice Protest verifies participation and *what its results may and may not be taken to mean*. It is written to a single governing principle: **the system must never claim more than it can show.** Where a signal is weak, this document says so; where a conclusion does not follow from the evidence, this document says so explicitly.

---

## 1. Purpose and scope

Voice Protest records **verified participation** in a public call (a *convocatoria*): a set of people who each confirm, through a verification step, that they support a stated demand directed at a public institution. At closure it produces a public report with an aggregate count, a geographic distribution, a reliability breakdown, and a tamper-evident integrity hash.

The system measures **who participated, under verifiable conditions**. It does not measure the truth of the underlying complaint, the representativeness of the participants relative to any wider population, or the legal standing of any participant. Those boundaries are not incidental; they are stated in every public report (see §5).

---

## 2. Verification model by scope

Each convocatoria has a scope, and the scope determines the verification path.

| Scope | Primary verification | Geographic signal |
|---|---|---|
| National / Global | One-time code (SMS) to a real phone number, via Twilio Verify | Country of SIM registration (phone prefix) |
| Institutional (email domain) | One-time code to an institutional email address on the declared domain | — |
| Institutional (census) | Institutional email plus peer vouching within a defined member set | — |
| Local / Regional | Phone verification, plus optional GPS reverse-geocoded against the declared territory's OpenStreetMap entity | GPS inside the declared municipality / region |

Institutional convocatorias additionally declare the institution's **country** (its seat). This is a locator used only to place the convocatoria on the map for discoverability; it is not an eligibility signal and produces no geographic breakdown of participants — eligibility remains the email domain.

For local and regional convocatorias, the geographic signal is offered at the moment of joining, through a one-time interstitial that presents location sharing as explicitly optional — both choices ("enable location" / "continue without") proceed to verification. Location never gates participation; it only strengthens the geographic evidence of an adhesion (see §4). (Revised 16 July 2026: an earlier version of this section described a 24-hour post-adhesion reinforcement window with a single-use token, offered as a follow-up action after joining. That mechanism was superseded, in the same development session that moved the geographic signal earlier in the flow, by capturing location before the adhesion call rather than after it — location travelling with the initial adhesion was judged more reliable than a later token. It is not part of the current implementation.)

The verification step is an **admission gate**, not a self-declaration: the code must be received and entered, or the email must be controlled, before an adhesion is recorded.

## 3. What constitutes a valid adhesion

An adhesion is admitted when all of the following hold:

- **Verified identity factor.** A one-time code was completed against a real phone number or an institutional email address.
- **Uniqueness.** Each verified identity counts **once per convocatoria**. This is enforced with a per-convocatoria *nullifier* — a one-way value derived from the identity pseudonym and the convocatoria id — so the same phone or email cannot produce two adhesions to the same call, while remaining unlinkable across calls by design.
- **Recipient admissibility.** The target is a public institution, validated server-side against Wikidata by traversing its subclass hierarchy (instance-of, then subclass-of) against a set of public-authority classes, not a fixed identifier list.
- **Source admissibility.** A documentary source must be supplied and must pass the source filter. Three conditions apply, all enforced server-side without exception: the source must not be a petition-aggregation platform (e.g. change.org, avaaz.org), since a petition signature is not the documentary basis the system requires; it must not be a social-media or user-generated-content post (e.g. Facebook, Instagram, X, YouTube, Telegram), since such a post is not subject to any editorial process and can be edited or deleted by its author; and it must show a verifiable connection to the reported event — the recipient's name, or distinctive words from the title and demands, must appear on the fetched page. This last condition (added 16 July 2026) is deliberately a minimum floor, not a quality bar: it rejects a source with no detectable connection to the event at all, but does not require a recognised outlet or a strong topical match — those are shown only as an informational indicator while drafting and on the event's detail screen, and never gate creation or participation.
- **Abuse controls.** Automated-request defences (humanity signal via reCAPTCHA, rate limiting, per-device de-duplication) were satisfied.

Risk level is a property of the convocatoria, set by its creator. For calls marked high or critical risk, the system **does not request or store location**; participation is pseudonymous and no GPS is collected. This behaviour is automatic and is disclosed on the convocatoria's detail screen.

## 4. Signals and their evidentiary strength

The system combines several signals. None is treated as proof; each carries a stated, bounded meaning.

- **SMS one-time code** — evidence that a real, reachable phone number was controlled at the moment of verification. It is not evidence of identity, nationality, or residence.
- **SIM country (phone prefix)** — a signal of the country in which the SIM is registered. It is a proxy, not a citizenship or residence determination.
- **Institutional email code** — evidence that the participant controls an address on the institutional domain. It supports an inference of affiliation; it does not establish role, status, or that the institution is represented.
- **GPS inside the declared territory** — a **geographic verification signal**: the device reported a position within the declared municipality or region, reverse-geocoded against its OpenStreetMap entity. GPS can be spoofed and is **not proof of location or residence**. It strengthens the geographic evidence of an adhesion; it does not certify where the person is.
- **IP geolocation** — a secondary, approximate signal only; the raw IP is not stored in clear. Empirical testing (July 2026) confirmed that mobile-carrier IP geolocation regularly resolves to the operator's gateway city rather than the participant's actual location — SIMs physically in Santander were geolocated to Llodio, Badajoz and Madrid across successive tests. For this reason IP never contributes territorial (municipal or regional) evidence; it contributes an approximate country signal only, and the public report labels any region-level breakdown derived from it as an estimate, distinct from GPS-verified territorial evidence.
- **Country classification** — the national/international grouping in the public report compares ISO 3166-1 alpha-2 country codes captured at verification time, never localized country names, so classification is independent of the interface or provider language.
- **Reliability score (60–95%)** — a measure of **evidence quality** for an adhesion, not a measure of certainty. The public report groups adhesions into reliability bands; the bands describe how much corroborating signal an adhesion carries, never a probability that the participant is "genuine".

### 4.1 Reliability score formula

The reliability score is computed at the moment of adhesion from the combination of signals present. The formula is deterministic and implemented server-side:

| Signals present | Score |
|---|---|
| GPS confirmed + SIM verified + IP country | 95% |
| GPS confirmed + SIM verified | 92% |
| SIM verified + IP country | 85% |
| SIM verified only | 75% |
| IP country only | 60% |

GPS confirmation means the device reported coordinates that reverse-geocode to the declared territory (municipality or region) via OpenStreetMap Nominatim, routed through the Voice Protest backend. SIM verified means a one-time SMS code was completed against a real phone number. IP country means the backend received a request from an IP address whose country-level geolocation matched the declared scope.

The score is a quality indicator of the verification event, not a probability that the participant is "genuine" or that their claim is true. A score of 95% means three independent signals corroborate the adhesion; it does not mean the adhesion is 95% "valid" in any normative sense.

The guiding distinction throughout: a signal is **evidence of a verification event**, not a conclusion about the person.

## 5. What the system does not demonstrate

Every public report carries an explicit "outside scope" statement. The methodology behind it:

- **Not residence.** A national or regional scope verifies SIM country or a geographic signal, not legal residence or registration in a territory.
- **Not membership of an affected group.** No territorial or institutional belonging is verified beyond the specific signal used (SIM country, email domain, GPS).
- **Not institutional role.** Email-domain verification does not establish whether a participant is, say, an active student versus staff, nor that the whole institution is represented.
- **Not the truth of the complaint.** Voice Protest records verified participation, not the validity of the denunciation.
- **Not representativeness.** The result measures those who chose to participate, not the wider affected population.

These limits are not disclaimers added after the fact; they are generated automatically per scope and shown alongside the result.

## 6. Integrity and auditability

At closure, the data required for public verification — public commitments, geographic distribution, reliability breakdown, final count, integrity hash — is written to a permanent record (`integrity_records`) that contains no personal data and is retained indefinitely.

- **Integrity hash.** Computed at closure with SHA256 over the convocatoria id, the final count, the reliability and city distributions, the adhesion timestamps, and internal identifiers. Unlike the identity pseudonyms elsewhere in this document (HMAC-SHA256, keyed with a server secret), this hash is deliberately unkeyed — a plain SHA256 — precisely so that anyone can recompute it themselves, from publicly published data, without needing any secret only Voice Protest holds. It is a tamper-evidence seal: any post-closure modification produces a different hash.
- **Public commitments.** A per-adhesion commitment (a one-way value derived from the nullifier) is recorded, designed to support independent verification.
- **Integrity versions.** Version 1, used before 18 July 2026, was an internal-only tamper-evidence mechanism: a report could be checked for consistency against the stored record, but doing so required trusting Voice Protest's own comparison. **Version 2 (in force since 18 July 2026, and confirmed working end-to-end on 9 August 2026) is independently, publicly verifiable**: the data needed to recompute the hash — public commitments, city and reliability distributions, timestamps — is published at a public endpoint, and the "Verify integrity" control in every closed report's page recomputes the hash in the visitor's own browser and compares it there, with no need to trust Voice Protest's own claim. The one guarantee this does not yet provide is **external anchoring** — a certified timestamp or a public ledger entry that would protect the seal even against a compromise of Voice Protest's own database. That remains planned, not yet built; `docs/integrity-log.md`, a manually-committed public record of each closure's hash, is a first, partial step toward it. Reports state which version they use.

## 7. Privacy and retention

Verification requires identifiers; the methodology bounds what is kept and for how long.

- **No raw identifiers.** Phone numbers become server-side HMAC-SHA256 pseudonyms; GPS coordinates are discarded immediately after geocoding. Raw IP is not stored in clear.
- **Irreversible anonymisation at 90 days.** Ninety days after a convocatoria closes, every individual or linkable field of its adhesions — phone hash, device identifier, nullifier, public commitment, fine-grained location, city and region — is permanently set to null. The row is kept as a non-identifying aggregate so the closed public report stays intact; the auditable snapshot lives in `integrity_records`.
- **Verified-device retention.** The device record that associates a random device identifier with a phone-number hash (enabling skip-OTP on later calls and duplicate prevention) is deleted after **270 days of inactivity** — a sliding window refreshed on each adhesion. A returning device re-verifies once by SMS. For a continuously active participant, the pseudonym persists only as long as participation continues.
- **One-time codes** are deleted after 7 days; **push subscriptions** at closure or when permission is revoked.
- **Database access.** Row Level Security is enabled on every table; all writes pass through the backend admission rules under a service-role key, never the public anonymous key.

## 8. Known limitations

Stated plainly, because credibility depends on naming them first.

- **Self-selection.** Participation is opt-in. The result is a clean signal (verified, unique participants) but not a representative sample; participation rate is reported where the eligible set is known (e.g. a census), and never estimated where it is not.
- **Declared preference, not behaviour.** An adhesion is a verified expression of support at a moment in time, not a commitment to act or vote.
- **Pseudonymity, not ballot secrecy.** The system provides strong pseudonymity, suitable for a public act of adhesion. It is **not** a secret-ballot mechanism and should not be presented as one; contexts that require guaranteed secrecy (for example, internal votes where participants fear reprisal) fall outside its current guarantees.
- **Geographic confidence is informative, not exclusionary.** A weak or absent geographic signal lowers the displayed confidence of an adhesion; it never blocks participation. The system measures geographic evidence, it does not gate eligibility on it.
- **Voluntary, reputational authority.** Voice Protest has authority only over those who choose to use it and to trust its report. Its only currency is credibility; this document exists so that the credibility rests on what the system verifiably does, not on how it is described.
