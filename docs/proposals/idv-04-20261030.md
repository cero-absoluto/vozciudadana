# IDV-04 — separar procedencia geográfica y puntuación institucional

30/10/2026. API y función SQL publicadas y verificadas. Evidencia: `docs/idv-04-publication-20261030.md`.

Se conserva debajo la descripción del candidato y su secuencia de validación.

El país aportado por GPS ya no cuenta como corroboración IP. La resolución marca
`ip_country_confirmed` solo tras una respuesta IP HTTP correcta, sin error y con
exactamente dos letras ASCII de país. GPS válido no genera una consulta IP extra.
La API calcula las señales según esa procedencia. El servicio institucional no
entrega país a la RPC salvo que exista esa evidencia IP; sigue excluyendo GPS.

Índices internos existentes según señales efectivas: identificación sola 75,
identificación e IP 85, identificación y GPS 92. La rama 95 requiere ambas señales;
la ruta actual usa GPS o fallback IP, por lo que no obtiene ambas a la vez.
Son índices internos, no probabilidades calibradas. No se reescriben históricos.

La función institucional existente conserva firma, SECURITY INVOKER, propietario,
ACL, bloqueo y consumo transaccional del OTP. Asigna 85 y email_otp,ip cuando existe
país IP válido; de lo contrario, 75 y email_otp. El fundador delega en la misma
función y conserva su excepción aprobada. Se documenta el contrato del parámetro
país sin añadir sobrecargas ni permisos. Los llamadores privilegiados siguen
siendo responsables de la procedencia que aportan.

SQL: `idv-04-institutional-score.sql`; reversión:
`idv-04-institutional-score-rollback.sql`. Ambos abortan ante deriva de definición,
propietario, ACL o SECURITY DEFINER. MD5 anterior
`51bc6c14aa8d5127a7467681b3bd844d`; posterior esperado
`d8e31ef25d9fba467752dc9f9ae911e4`. CREATE OR REPLACE mantiene ACL y propietario.

rutas/servicio anteriores más ocho casos del payload institucional/fundador.
